# 日テレ放送データの運用

公式資料を放送日ごとにまとめ、OpenAIで企画名・出演者・訪問国を抽出します。資料の取得と日付の振り分け、保存だけをコードで行います。出演者と訪問国の厳密な対応は求めず、企画の出演者一覧を各訪問国に紐付けます。

更新処理の共通コードは `scripts/broadcasts/` にあります。`sources.py` が資料取得、`openai.py` がAPI通信、`pipeline.py` が日付単位の抽出とデータ変換、`common.py` が保存・通信の共通処理を担当します。入口は `scripts/update-ntv.py` です。

## 実行

Python 3.10以上の標準ライブラリで動きます。テストはPython 3.11以上、CIは3.12です。APIキーは環境変数 `OPENAI_API_KEY` に設定し、ファイルやログには保存しません。

```bash
python3 scripts/update-ntv.py
# 別の出力先で検証。初回は既存判定を引き継がず再照会する場合があります。
python3 scripts/update-ntv.py --output-dir /tmp/ntv-review
# 保存済み記事・API回答だけで実行。未保存の回答は保留。
python3 scripts/update-ntv.py --input .cache/ntv/articles.json --offline --output-dir /tmp/ntv-review
python3 scripts/update-ntv.py --validate-only
python3 -m unittest discover -s scripts/tests -v
```

更新対象は実行日（日本時間）の1か月前から当日までです。前月同日が存在しない場合は前月末を使います（例: 3月31日なら2月28日、うるう年は29日）。`--since` と `--today` で対象期間を指定できます。未来の放送は追加しません。別の出力先を初めて使う場合、元のWikipedia行だけを引き継ぎ、追加分は別途生成します。

## 取得と抽出

1. [公式記事JSON](https://www.ntv.co.jp/q/articles.json)から、予告タイトルと `OAまとめ` タグで記事を選び、HTMLを本文テキストにします。見出しでの企画分割や出演者欄の解析は行いません。
2. 予告はタイトルの月日と公開年から放送日を取得し、OAまとめは記事の日付を使います。[日本海テレビ番組表](https://www.nkt-tv.co.jp/program/)の掲載中のイッテQ詳細リンクと保存済み番組表も利用します。
3. 同じ日の全資料を一度のOpenAI Responses API（`gpt-6-sol`）呼び出しに渡します。企画の重複統合、出演者、都市・地域から国への変換、総集編等を新規訪問として数えない判断をAIが行います。OAまとめがある場合は実際の放送内容を優先するよう指示します。
4. `projects` 配列で企画名・出演者一覧・国コード一覧・根拠URLを受け取ります。意味の正しさは信頼し、JSON構造・有効な国コード・入力資料のURL等の形式だけ検査します。総集編・アワードも企画名を残し、新規訪問がない企画は `countries: []` にします。出演者が不明なら `performers: []` を許容します。

`countries.json` は国コードと表示名の対応表だけです。地名辞書、予告優先の分岐、企画IDの突合、手動訂正ファイルは使いません。

## 差分更新と保存

- 放送履歴は `generated/decisions.json` の日付・企画一覧に保持します。総集編等もタイトルと出典が残り、レポートに掲載します。`src/data/episodes.json` は訪問国がある企画だけを保存するため、総集編は地図の件数に加わりません。
- 元のWikipedia行1,376件はハッシュで内容・順序を保護し、`src/data/episodes.json` の追加分だけを更新します。
- `generated/decisions.json` の `broadcasts` に日付ごとの資料・入力ハッシュ・回答・状態を保存します。入力にはモデル・プロンプト・JSON形式も含みます。
- 同じ入力の処理済み日は再照会しません。正常な空配列も処理済みです。
- 資料の追加・変更時はその日を再処理し、成功したらその日の追加記録全体を置き換えます。空配列ならその日の追加記録を削除します。
- API失敗時は以前の企画一覧と訪問記録を保持し、次回再試行します。取得対象外の日も保持します。
- 取得元から消えた資料は保存済み本文を使い続けます。同じURLの本文が更新された場合は新しい本文を使います。
- 旧企画単位の記録も、日付単位の抽出に成功するまでは保持します。
- API回答は `.cache/ntv/openai/`、使用量は `.cache/ntv/run.json` に保存します。429・一時的な通信失敗は最大3試行、APIの各試行は90秒でタイムアウトします。

日付をまたぐ資料の対応付けは行いません。OAまとめの公開が遅れた場合は記事の日付で処理します。予告もOAまとめも番組表もない日は取得できません。これらは現在の運用で許容する扱いです。

## GitHub Actions

日曜23時JSTと手動実行で、最新mainを取得して処理します。Secretsの `OPENAI_API_KEY` を利用し、前回成功時の資料・APIキャッシュを復元します。判定はmainにも保存するため、90日保持のキャッシュが失効しても同じ入力を再照会しません。

テスト・データ検証・lint・build成功後、訪問データ・判定JSON・レポートの3ファイルだけをmainへ自動コミット・pushします。差分がなければコミットしません。mainが処理中に進んだ場合は停止し、強制pushしません。

pushには `GITHUB_TOKEN` を使い、公開サイトはCloudflareのGit連携で更新します。保留があっても取得できた分は公開します。ActionsのSummaryと `.cache/ntv/run.md` には今回AIに送った日付・企画、変更なしで再利用した日付、キャッシュ利用、保留を区別して表示します。全保存履歴は `generated/report.md` に残します。API回数・使用量・対象期間は `run.json` にも記録します。対象期間外の履歴は削除せず、再処理しません。
